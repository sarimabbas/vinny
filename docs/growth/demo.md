# Record a real Vinny connection

Deliverable: one 30–45 second screen recording, readable without sound, plus a poster frame. Use the published Vinny build on a Mac and a second machine with a tested viewer. The Linux development environment cannot validate or record the native app.

Use a clean test desktop containing only a sample document. Hide notifications and avoid personal files, passwords, addresses, hostnames, and certificate secrets. Enable a secure connection method from the guide before filming. Never publish a password prompt containing a real password.

| Time | Real action | Caption |
| --- | --- | --- |
| 0–5 s | Open Vinny and show the configured display selector | Choose the display to share |
| 5–12 s | Show maximum width, frame rate, and listener configuration | Configure each listener |
| 12–22 s | Cut to the other machine connecting with the tested viewer | Connect from your VNC viewer |
| 22–30 s | Move a harmless window on the remote desktop | Control the selected display |
| 30–38 s | Disable Remote control and demonstrate blocked viewer input | Switch to view-only |
| 38–45 s | Show the working remote desktop and repository URL | Install Vinny. Follow the connection guide. |

Do not claim that a changed option applies instantly unless the actual build does that. Show any required Apply, restart, or reconnect step. Include captions or the surrounding written guide that name the viewer, macOS version, and Vinny version used.

Before publishing, watch the full recording at mobile width, verify captions and cursor movement are visible, and check for private data frame by frame around connection dialogs. Export a compact MP4, retain the original recording privately, and choose a poster frame that shows a real connection. Add a descriptive text link to the recording in the README and embed a video with controls and a fallback link on the website. Avoid autoplay with sound.
